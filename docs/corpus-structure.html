1. Overview

Each language in the NTU Multilingual Corpus is stored in its own SQLite database (e.g. eng.db, jpn.db, cmn.db). All databases share the same schema. The corpus contains parallel texts across multiple languages, with annotations for word senses (linked to wordnet synsets), sentiment, and document structure.

2. Database Schema

Core tables

corpus(corpusID, corpus, title, url)
  ↓ 1:N
doc(docID, doc, title, url, subtitle, corpusID)
  ↓ 1:N
sent(sid, docID, pid, sent, comment, usrname)
  ↓ 1:N
word(sid, wid, word, pos, lemma, cfrom, cto, comment)

stype(sid, stype, comment)          ← document structure
concept(sid, cid, clemma, tag)      ← sense annotation
cwl(sid, cid, wid)                  ← concept–word link
sentiment(sid, senti, strength, ...)← sentiment annotation

Key relationships

  • A corpus groups related documents (e.g. “Sherlock Holmes”, “Singapore Tourism”).
  • A doc is a single text (e.g. one short story, one web page, one essay).
  • A sent is a sentence (or sentence-like unit: heading, author line, list item).
  • A word is a single token within a sentence, identified by (sid, wid).
  • The stype table records the structural role of each sentence in the original document.

3. Sentence Types (stype)

The stype table assigns a structural type to each sentence. Every sentence in a document should have exactly one stype row. The type determines how the sentence is displayed (as a heading, paragraph, list item, etc.).

Schema

CREATE TABLE stype (
    sid     INTEGER,    -- references sent(sid)
    stype   TEXT,       -- structural type code
    comment TEXT,       -- optional annotation (e.g. "Chapter 1", "BOOK ONE")
    FOREIGN KEY(sid) REFERENCES sent(sid)
);

Heading levels

The heading hierarchy corresponds to document structure:

  • h1 — the overall document title (at most one per document).
  • h2 — top-level sections within the document.
  • h3 — subsections or chapters. The comment column may carry a label like “Chapter 5” or “BOOK ONE”.
  • h4–h7 — deeper nesting levels (rarely used).
  • h0 — a pragmatic code for short documents (web pages, catalogue entries) where the “title” sentence doubles as the main heading. Displayed at the same level as h2.

4. Display Rendering

The corpus display viewer (scripts/make_display.py) generates static HTML pages for each document. The stype value controls the HTML wrapper element for each sentence:

stypeHTML output
h1–h7 <h1>–<h7>
h0 <h2>
p <p>
item <p class="stype-item">
author <p class="stype-author">
translator <p class="stype-translator">
(any other or missing) <p> (fallback)

CSS classes

The display stylesheet (display/assets/corpus.css) defines the following classes for non-standard sentence types:

.stype-author, .stype-translator
Italic text in a muted colour, with reduced bottom margin. Visually distinguishes attribution lines from body text.
.stype-item
Left-indented (2rem) with a light grey left border. Visually sets numbered principles and list items apart from surrounding prose.
