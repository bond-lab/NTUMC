## 6. Recommendations

1. **Restore server access first.** Everything hinges on `compling.upol.cz`. The `release.sh` script downloads all canonical DBs from there. Without access, you cannot get the current state of `eng.db`, `cmn.db`, etc. (the Feb 2025 snapshot is the best local copy).

2. **Run `fixwn.py` against `build/wn-ntumc.db`.** The 5 W501 errors in Czech (adjective synsets with noun hypernyms) and the 758 W201 empty entries in English are the most actionable issues. Run:
   ```
   .venv/bin/python scripts/fixwn.py build/wn-ntumc.db
   ```
   The script is idempotent and has a `--dry-run` flag.

3. **Run `fixlinks.py` against `build/wn-ntumc.db`.** Fixes W403 (duplicate synlinks) and W404 (missing reverse relations). No log exists to confirm whether this was run before the Feb 2025 download.

4. **Investigate the ind tag count decrease.** The build/ind.db has 3,943 fewer `x`+`w` tags than the 2016 snapshot. If the intent is that more items should be tagged as `x`/`w` in the current version (i.e., corrections), this is correct. If the 2016 version had better coverage, something was lost. Recommend querying `concept_log` in build/ind.db to see what tag changes occurred.

5. **Do not merge the 2016 work/ snapshots into build/.** The build/ DBs (downloaded Feb 2025) are strictly newer than all work/ snapshots. The 2016 files are historical backups; the 2024 `eng-new.db` fixes have already been incorporated by the server.

6. **Add cross-language link DBs to the release pipeline.** `release.sh` currently does not download `eng-cmn.db`, `eng-jpn.db`, etc. from the server. If those link databases are part of the intended release, add them to `ALL_DBS` in `release.sh`.

7. **Populate `zsm.db` and `yue.db`.** Both have 0 tagged concepts. `zsm.db` has 1 document; `yue.db` has 9 Cantonese YouTube comment documents. These corpora are present but unannotated.

8. **Handle `wilde.db`.** The `wilde.db` in the repo root (Oscar Wilde corpus, 0 data) is untracked and likely a scratch file. Either populate it or delete it from the working tree.

9. **Clarify `ces-cnc.db` in `data/`.** `data/ces-cnc.db` is a 0-byte placeholder (2025-02-22). The actual Czech corpus is in `build/ces.db` downloaded from compling. Clarify whether `data/ces-cnc.db` was meant to hold the original CNC source data.
